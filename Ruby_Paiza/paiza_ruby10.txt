## 目次 ― このファイルで出てくる知識・メソッド
============================================================

### メソッド
  Integer#round             小数を四捨五入して整数に変換する
  Hash#[]                   ハッシュからキーで値を取り出す（例: p[:freq]）

### 構文・記法
  { freq: line[0], price: line[1] }           map の中でハッシュを作って返すパターン
  week == 1 || (week - 1) % p[:freq] == 0    1週目 OR 周期に合致する週を判定する
  (week - 1) % p[:freq] == 0                  1週目を起点(0)にして freq 週おきを余りで判定
  week_price * 0.85                            割引率を掛けて価格を計算する
  week_price.round                             Float になった金額を整数に戻す

### 知識・パターン
  n.times.map do...end でハッシュ配列を作る   入力1行ごとにハッシュを生成して配列に格納する
  ループ内でカウンタを使う                    item_count で週ごとの個数を数えて条件分岐
  周期判定パターン                            (現在地 - 1) % 頻度 == 0 で「〇回おき」を判定
  || による例外ルールの追加                   week == 1 を OR で加えて1週目を強制的にヒットさせる
  シンボルキーのハッシュ                      { freq:, price: } のようにシンボルをキーに使う

============================================================

n, m = gets.split(" ").map(&:to_i)      #「n」は、商品の種類数、「m」は、何週間後までか

products = n.times.map do
    line = gets.split(" ").map(&:to_i)
    { freq: line[0], price: line[1] }   # 各商品ごとの購入頻度と価格のセットを読み込む
end

total_cost = 0

(1..m).each do |week|   # 週ごとにかかる費用を見ていく
    week_price = 0
    item_count = 0
    
    products.each do |p|    # 各商品を順にブロック変数に入れている。
        if week == 1 || (week - 1) % p[:freq] == 0      # 単純に１週間目なのか、頻度の軸で見た週目と、配列の頻度で倍数を出す。
            week_price += p[:price]
            item_count += 1
        end
    end
    
    if item_count >= 3
        week_price = week_price * 0.85
    elsif item_count == 2
        week_price = week_price * 0.90
    end
    
    total_cost += week_price.round
end

puts total_cost

## このコードの仕組み

### 全体の流れ

1週目〜M週目まで週ごとにループを回し、その週に届く商品の金額を合計する。
3個以上で15%引き、2個で10%引きの割引を適用してから total_cost に加算する。

### week == 1 || (week - 1) % p[:freq] == 0 の意味

問題の前提：「1週目にすべての商品が届く」

  week == 1                      # 1週目は全商品が届く（特別ルール）
  (week - 1) % p[:freq] == 0    # 2週目以降：1週目を起点に freq 週おきか判定

### なぜ week - 1 するのか

week そのままで `week % freq == 0` にすると、
freq = 2 のとき 2, 4, 6... 週目がヒットしてしまう（1週目スタートがずれる）。

`week - 1` にすることで、1週目を「0」として計算できる。

  freq = 2 のとき
  week=1 → (1-1) % 2 = 0  ✔（1週目ルールで届く）
  week=2 → (2-1) % 2 = 1  ✗
  week=3 → (3-1) % 2 = 0  ✔（2週おきなので3週目に届く）
  week=4 → (4-1) % 2 = 1  ✗
  week=5 → (5-1) % 2 = 0  ✔

### week_price.round が必要な理由

0.85 や 0.90 をかけると小数になる。
round で四捨五入して整数に戻してから total_cost に加算する。

「何かを順に見ていくとき、その中に含まれているものの頻度を導く（周期的に訪れるタイミングを捉える）」という考え方は、プログラミングやシステム設計、あるいは日常のスケジュール管理などでもめちゃくちゃ汎用性の高い**超基本の思考パターン**です。

今回コードでやったこの仕組みを、もっと大きな視点（抽象的な考え方）として分解して解説しますね。

---

### 1. この考え方の本質：「数直線（タイムライン）」と「割り算の余り（周期）」の組み合わせ

何かを順番に見ていくとき（今回は1週目、2週目、3週目……と進むカレンダーのタイムライン）、周期的に繰り返されるイベントを捉えるには、次の2つの要素をセットで考えます。

1. **基準（スタート地点）はどこか？**
2. **間隔（ピッチ）はいくつ刻みか？**

この2つが揃うと、任意のタイミング（いま何番目か）が「そのイベントの発生日かどうか」を、数学的に一発で判定できるようになります。

---

### 2. 思考のステップ（どうやって頭の中で組み立てるか）

「順に見ていきながら、特定の頻度・周期のものを捉える」ときは、次の3ステップで組み立てます。

#### ① 「今、全体の中でどこにいるか」を把握する（カウンタ）

* 今回で言うと、`week` という変数で「いま1週目、2週目、3週目……」と1つずつ進めていく部分です。
* これにより、時間の流れを数字として捉えられるようになります。

#### ② 「最初のスタート地点からのズレ（経過量）」に直す

* 世の中の多くの周期イベントは「1週目スタート」「1日目スタート」といった人間にとって分かりやすい数字（1始まり）で始まります。
* しかし、周期を計算するときは「スタート地点を『0』とする」と一気に計算がラクになります。
* だから、今回の `week - 1` のように **「今いる位置 － スタート地点」** をして、「そこから何回分（何週間分）進んだか（経過したか）」という純粋な距離に直します。

#### ③ 「間隔（頻度）」で割ったときの「余り」を見る

* ここが魔法の部分です。経過した距離を、商品の頻度（`p[:freq]`）で割ります。
* 例えば、頻度が「3週に1回」なら、経過週数が `0, 3, 6, 9...` のときだけ、3で割ったときの余りが「0」になります。
* つまり、「余りが0になる瞬間＝周期のピッチにぴったりハマった瞬間」とみなすわけです。

---

### 3. 他の場面でこの考え方が使われる例

この「タイムライン × 経過時間 ％ 頻度 == 0」という考え方は、実はゲームや実務のシステムでもめちゃくちゃ使われています。

* **ゲームの敵の行動パターン**
* 「1フレーム目からスタートして、3フレームに1回、敵が弾を撃つ」というときも、`(frame - 1) % 3 == 0` で判定します。


* **カレンダーの繰り返し予定（「隔週の金曜日」など）**
* 「特定の日付から数えて、14日（2週間）ごとの倍数の日」を計算してカレンダーに予定を自動で配置する仕組みも、まったく同じ考え方です。


* **アニメーションやコマ送り**
* 「10フレームに1回、キャラクターの画像を切り替える」というときも、経過フレームを周期で割った余りを見て制御します。



---

### まとめ

「順に見ていくときに頻度を導く」という考え方の正体は、
**『全体の流れ（カウンタ）を、スタート地点からの距離に直し（`week - 1`）、それを周期の数字で割った余り（`% freq == 0`）を見ることで、ジャストのタイミングを浮かび上がらせる』**
という手法です。

一度この「タイムラインと余りの関係」の感覚を掴むと、似たような周期やスケジュールの問題をみたときに「あ、あの仕組みね」と一発で構造が見えるようになりますよ！
