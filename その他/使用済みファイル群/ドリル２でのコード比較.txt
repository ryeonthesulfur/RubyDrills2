【`Tweet::create`の裏側のコード（簡易版）】

`Tweet::create([...])`の裏側で動いている仕組みを、簡易的なPHPクラスで再現すると以下のようになります。

```php
// Laravelのモデルを簡易的に再現したクラス
class Tweet {
    // モデルが持つプロパティ（DBのカラムに相当）
    public ?string $text = null;
    public ?string $image = null;
    public ?int $user_id = null;

    /**
     * createメソッド。
     * 配列を受け取り、インスタンス生成からDB保存までを一括で行う。
     * このように、自分自身のインスタンスを生成して返すメソッドを「ファクトリメソッド」と呼びます。
     */
    public static function create(array $attributes): static
    {
        // 1. まずは自分自身の空のインスタンスを作る
        $tweet = new static();

        // 2. 渡された配列のデータで、インスタンスのプロパティを埋める
        $tweet->fill($attributes);

        // 3. データベースに保存する
        $tweet->save();

        // 4. 完成したインスタンスを返す
        return $tweet;
    }





    /**
     * プロパティを配列で一括設定するメソッド。
     * これが「裏側でセッターが呼ばれている」の正体です。
     */
    public function fill(array $attributes): void
    {
        // 配列をループで回す
        foreach ($attributes as $key => $value) {
            // $keyには'text'や'user_id'が、
            // $valueにはその値が入る。
            // `$this->{$key}` という書き方で、プロパティ名を動的に指定できる。
            // 例: $this->text = '投稿内容';
            $this->{$key} = $value;
        }
    }

    /**
     * データベースに保存するフリをするメソッド
     */
    public function save(): void
    {
        echo "--- データベースに保存処理が実行されました ---\n";
    }
}

// 実行例
$requestData = [
    'text' => 'Laravelは便利！',
    'image' => null,
    'user_id' => 1,
];

$newTweet = Tweet::create($requestData);

echo "作成されたTweetオブジェクトの中身:\n";
print_r($newTweet);
```

このコードの`fill`メソッドが、Rubyで学んだ「ハッシュで初期化する`initialize`」と全く同じ役割を果たしていることがわかります。
フレームワークは、こうした基本の組み合わせで成り立っているのです。

【応用2】コントローラーからビューへデータを渡し、フォームに埋め込む

「そしてビューのファイルでこいつ（$requestData）を入力フォームに埋め込んでおけばいいわけ？」

はい、その通りです。それがMVCの最終的なデータの流れになります。

1.  **コントローラー**が、データベースから特定のデータ（例: ID=1のTweet）を取得します。
2.  コントローラーは、取得したオブジェクトをビューファイルに渡します。
3.  **ビュー**は、渡されたオブジェクトのプロパティを使って、フォームの初期値を設定します。

これをLaravelのコードで見てみましょう。

### コントローラー (`TweetsController.php`)
```php
public function edit($id)
{
    // 1. データベースから編集したいTweetを探す
    $tweet = Tweet::findOrFail($id);

    // 2. 探した$tweetオブジェクトを'tweets.edit'ビューに渡す
    return view('tweets.edit', ['tweet' => $tweet]);
}
```

### ビュー (`resources/views/tweets/edit.blade.php`)
```html
{{-- 3. コントローラーから渡された$tweetオブジェクトのtextプロパティを、textareaの中に表示する --}}
<textarea name="text">{{ $tweet->text }}</textarea>
```

このように、コントローラーで用意したデータオブジェクトを、ビューでフォームの初期値として埋め込む、という連携で編集画面は作られています。




`['tweet' => $tweet]` は、「ビューファイルの中では `$tweet` という名前の変数で、このデータを扱ってくださいね」という意味の**荷札（ラベル）**です。

・`'tweet'` (左側): ビューファイル内で使われる**変数名**になります。
・`$tweet` (右側): 実際にビューに渡される**データ本体（オブジェクト）**です。

この荷札のおかげで、ビューファイル（`edit.blade.php`）では `$tweet->text` のように、コントローラーから渡されたオブジェクトにアクセスできるのです。
