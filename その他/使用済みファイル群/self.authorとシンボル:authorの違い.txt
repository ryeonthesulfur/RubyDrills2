【`self.author`の`author`はメソッド？シンボル？】徹底解説

「`self.author`の`author`はゲッターメソッドの`author`？それともシンボルの`:author`のこと？」

これは非常に鋭い質問です。結論から言うと、

-   `self.author` の `author` は、**ゲッターメソッド `def author` のこと**です。
-   `self.author = ...` の `author` は、**セッターメソッド `def author=` を呼び出すためのキーワード**です。

どちらも、シンボル `:author` そのものではありません。

==================================================
1. シンボル `:author` の役割：「メソッドを作るための設計図の名前」
==================================================

まず、シンボル `:author` は、それ自体がメソッドなのではなく、**「メソッドやハッシュのキーに付ける、ただの名前（ラベル）」**だと考えてください。

`attr_accessor :author`

このコードは、「Rubyさん、`:author`という名前のラベルを使って、ゲッターとセッターのメソッドを自動で作ってください」という**お願い**です。

このお願いを受けて、Rubyは内部的に以下の2つのメソッドを生成します。

```ruby
# :author というシンボルから作られたゲッターメソッド
def author
  @author
end

# :author というシンボルから作られたセッターメソッド
def author=(new_author)
  @author = new_author
end
```

==================================================
2. `self.author` の役割：「作られたメソッドを呼び出すスイッチ」
==================================================

そして、`self.author` や `self.author = ...` は、上記で**作られたメソッドを呼び出すためのスイッチ**の役割を果たします。

-   `puts self.author`
    これは、「自分自身（`self`）の、`author`という名前の**ゲッターメソッド**を呼び出せ！」という命令です。

-   `self.author = "田中"`
    これは、「自分自身（`self`）の、`author=`という名前の**セッターメソッド**を呼び出せ！」という命令です。

### `initialize` の中での使われ方

`initialize(attributes = {})` の中の `self.author = attributes[:author]` というコードは、この関係性を非常によく表しています。

```ruby
self.author = attributes[:author]
#  (A)      =      (B)
```

-   **(A) `self.author`**: 左辺にあるこれは、**セッターメソッド `author=` を呼び出す**スイッチです。
-   **(B) `attributes[:author]`**: 右辺にあるこれは、`attributes`というハッシュの中から、**`:author` というシンボルをキーにして**値を取り出しています。

このように、左辺と右辺で、元は同じ `:author` というシンボルから派生したものが使われていますが、その役割は「メソッド呼び出しのキーワード」と「ハッシュのキー」として、全く異なっています。

==================================================
まとめ
==================================================

1.  **シンボル `:author`** は、メソッドを作るための「**名前のラベル**」。
2.  **`attr_accessor`** は、そのラベルを元に `def author` と `def author=` という「**メソッドの実体**」を作る。
3.  **`self.author`** や **`self.author = ...`** は、作られたメソッドの実体を呼び出すための「**スイッチ**」。

この3段階の関係性を理解すると、Rubyのクラスの動きがよりクリアになります。
