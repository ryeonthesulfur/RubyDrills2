【attr_accessorとバリデーション】セッターにルールを追加する正しい方法

「ルールを設けたい時は、`attr_accessor`は使えないの？」
この疑問に対する答えは、「半分YESで、半分NO」です。

より正確に言うと、**「`attr_accessor`をそのまま使うのではなく、ゲッターとセッターを分解して考える」**のが正解です。

==================================================
1. なぜ `attr_accessor` だけではダメなのか？
==================================================

`attr_accessor :author` は、以下の2つのメソッドを自動生成する便利なショートカットでした。

```ruby
# 読み取り用（ゲッター）
def author
  @author
end

# 書き込み用（セッター）
def author=(new_author)
  @author = new_author
end
```

ご覧の通り、自動生成されるセッターは、ただインスタンス変数に値を代入するだけの非常にシンプルなものです。
ここに「名前が空ではいけない」といった独自のルールを挟む余地はありません。



==================================================
2. ベストプラクティス：「ゲッターは自動、セッターは手書き」
==================================================

そこで、プロの開発現場では、このような「いいとこ取り」の手法がよく使われます。

-   **ゲッター（読み取り）**: 面倒な手書きはせず、`attr_reader`に任せて自動生成する。
-   **セッター（書き込み）**: ルールを実装したいので、`def author=`の形で**手書きで上書き（オーバーライド）する。**

この考え方で書いたコードがこちらです。

```ruby
class Article
  # ゲッターは自動生成におまかせ
  attr_reader :author, :title, :content

  # authorのセッターだけ、ルールを加えて手書きする
  def author=(new_author)
    # バリデーションルール：もし名前が空なら、エラーを発生させる
    raise "著者名は空にできません" if new_author.nil? || new_author.empty?
    @author = new_author
  end

  def initialize(author, title, content)
    # 必ず「公式な窓口」であるセッターを呼び出す
    self.author = author # 手書きしたセッターが呼ばれ、ルールがチェックされる！
    @title = title       # こちらはセッターを上書きしていないので、直接代入でOK
    @content = content   # こちらも同様
  end
end

# 実行してみる
# Article.new("") #=> `initialize`の中でセッターが呼ばれ、エラーが発生する！
article = Article.new("阿部", "Rubyの素晴らしさ", "Awesome Ruby!")
puts article.author #=> 阿部

# article.author = "" #=> 後から空文字を代入しようとしても、セッターがエラーを発生させる！
```

このように、ゲッターは`attr_reader`の便利さを享受しつつ、ルールを加えたいセッターだけをピンポイントで手書きすることで、
コードの可読性と安全性を両立させることができます。
