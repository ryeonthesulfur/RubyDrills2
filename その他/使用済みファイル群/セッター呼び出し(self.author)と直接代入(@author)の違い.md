# なぜ `self.author`？
## セッター呼び出しとインスタンス変数への直接代入の違い

`initialize` メソッドの中で、なぜ `@author = ...` ではなく `self.author = ...` と書くのか？  
これは、Rubyのオブジェクト指向における非常に重要な概念を理解するための鍵となります。

## 1. 結論：これは「メソッド呼び出し」である

この2つの書き方は全く違う意味を持ちます。

| 書き方 | 意味 |
|:-------|:-----|
| `self.author = "阿部"` | **セッターメソッド `def author=(value)` を呼び出す**ための、Rubyの特別な書き方（シンタックスシュガー） |
| `@author = "阿部"` | **インスタンス変数 `@author` に直接値を代入する**処理 |

`self.author = "阿部"` と書くと、Rubyは裏側で `self.author=("阿部")` と解釈し、手書きした、あるいは `attr_accessor` で作られた以下のセッターメソッドを探して実行します。

```ruby
def author=(new_author)
  @author = new_author
end
```

## 2. なぜ `initialize` の中でセッターを呼ぶのか？

「結局どちらもインスタンス変数に値を入れているなら、同じじゃないの？」と思うかもしれません。  
しかし、セッターメソッドを呼び出すことには、**「一貫性と安全性を保つ」** という大きなメリットがあります。

例えば、`author` には空の文字列を許可したくない、というルールを追加したとします。

```ruby
class Article
  def author=(new_author)
    # バリデーションロジック
    if new_author.nil? || new_author.empty?
      puts "エラー：著者名は空にできません。"
      return  # 代入せずに処理を終了
    end
    @author = new_author
  end

  def initialize(attributes = {})
    self.author = attributes[:author]  # セッターを呼ぶ！
  end
end
```

もし `initialize` の中で `@author = attributes[:author]` と直接代入してしまうと、このバリデーションロジックは**完全に無視されてしまいます**。

そのため、本来はセッターの役割も持っている `initialize` メソッドのセッター部分だけをあえて分離させてルールを記述し、`initialize` メソッド内で `self.セッターメソッド` を呼び出すという構造にします。

`self.author = attributes[:author]` と書くことで、インスタンスが作られる最初の瞬間から、必ずバリデーションロジック（公式な窓口）を通るようになります。これにより、不正なデータを持つインスタンスが作られるのを防ぐことができます。

---

## まとめ

| 書き方 | 種類 | 特徴 |
|:-------|:-----|:-----|
| `self.author = ...` | セッター呼び出し | **推奨。** 公式な窓口を通るためバリデーションなどのロジックを一元化できる。安全性が高く、仕様変更にも強い |
| `@author = ...` | 直接代入 | 裏口から直接書き換える行為。セッターに書かれたロジックを無視するため、意図しないバグの原因になりやすい |
