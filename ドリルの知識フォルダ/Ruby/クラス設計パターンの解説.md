## 用語の整理（まず読んで）

このファイルを読む前に、出てくる言葉の意味を確認しておく。

| 用語 | 意味 |
|:-----|:-----|
| **インスタンス** | クラス（設計図）から `.new` で作った実体。`Food.new("ラーメン", 500)` で作られた個々のデータのかたまり |
| **インスタンス変数 `@`** | 各インスタンスが個別に持つ変数。`@name` など。そのインスタンスだけのもの |
| **クラス変数 `@@`** | クラス全体で共有する変数。`@@foods` など。クラスのどのメソッドからでも同じものにアクセスできる |
| **クラスメソッド** | `def self.xxx` で定義するメソッド。`Food.input` のようにクラス名から直接呼ぶ。インスタンスを作らなくても使える |
| **引数リレー** | データを持った変数を、メソッドを呼ぶたびに引数として渡して持ち回ること。`post_item(cart)` → `return a_cart` → `cart = post_item(cart)` の繰り返し |
| **ゲッターメソッド** | インスタンス変数の中身を外から読み取るためのメソッド。`attr_reader` で自動生成できる。`food.name` のように呼ぶ |
| **`attr_reader`** | ゲッターを自動生成する記法。`attr_reader :name` と書くと `def name; @name; end` が自動で作られる |

---

これまでのドリルでは、空の配列を用意し、それをメソッドの引数として渡すことでデータを管理していました。しかし、クラスの「クラス変数」を使うことで、より洗練された設計が可能です。このドキュメントでは、その違いとメリットを解説します。

---

## 1. データの持ち場所：引数 vs クラス変数

#### 今までの方法：メソッドの引数で配列を渡す

```ruby
# メソッドの外に配列を用意
cart = []

def post_item(a_cart)
  # ... 商品データを生成 ...
  new_item = { name: "りんご", price: 120 }
  a_cart << new_item # 引数で渡された配列にデータを追加
  return a_cart
end

# 呼び出すたびに引数として cart を渡し、戻り値を受け取る必要がある
cart = post_item(cart)
```

この方法では、データを保持する `cart` 配列を、メソッドを呼び出すたびに引数として渡し、戻り値を受け取る必要がありました。これを「引数で持ち回る」「引数リレー」と表現できます。

---

#### 今回の方法：クラス変数で配列を持つ

```ruby
class Food
  # クラス自身がデータを保持する場所を持つ
  @@foods = []

  def self.input
    # ...
    food = Food.new(name, calory)
    # 引数で渡さなくても、クラス内のどこからでも @@foods にアクセスできる
    @@foods << food
  end
end
```

**最大の違いは「配列を引数で渡す必要がない」ことです。**
`@@foods` というクラス変数は、`Food`クラスに紐づく共有の保管場所です。`Food`クラスのどのメソッドからでも `@@` を使って直接アクセスできるため、メソッド間でデータを持ち回る必要がなくなります。

## 2. インスタンス生成の場所：クラスの外 vs クラスの中

#### 今までの方法：クラスの外で `new` する

```ruby
class Student
  def initialize(name, age)
    @name = name
    @age = age
  end
end

# クラスの外で、使う側がインスタンスを生成する
student = Student.new("ゆき", 33)
```

これは最も基本的なパターンです。クラスは設計図に徹し、インスタンスの生成はクラスを利用する側（外側）の責任で行います。

#### 今回の方法：クラスメソッドの中で `new` する

```ruby
class Food
  @@foods = []
  attr_reader :name, :calory

  def initialize(name, calory)
    @name = name
    @calory = calory
  end

  # クラスメソッド
  def self.input
    # ... ユーザーからの入力受付 ...

    # クラスメソッドの中でインスタンスを生成
    food = Food.new(name, calory)

    # 生成したインスタンスをクラス変数に格納
    @@foods << food
  end
end

# 使う側は input メソッドを呼ぶだけ
Food.input
```

この設計では、「ユーザーからの入力受付 → インスタンス生成 → データの一覧への追加」という一連の処理を、`Food.input` という一つのメソッドにまとめています。

**利点：** 使う側は `Food.new` や `@@foods` の存在を意識する必要がありません。ただ `Food.input` を呼び出すだけでデータ登録が完了するため、クラスの使い方が非常にシンプルになります。

## 3. データの取り出し方：ハッシュ vs オブジェクト

#### 今までの方法：ハッシュのキーでアクセス

```ruby
# データはハッシュとして配列に保存されていた
cart = [
  { name: "ラーメン", price: 500 }
]

# 取り出すときはキーを指定する
puts cart[0][:name] #=> "ラーメン"
```

ハッシュでデータを管理する場合、`[:キー名]` という形式で値を取り出します。

#### 今回の方法：オブジェクトのメソッドでアクセス

```ruby
# @@foods には Food オブジェクトが保存されている
# 例: @@foods = [ <Food @name="メロンパン">, <Food @name="スパゲティ"> ]

class Food
  attr_reader :name, :calory
  # ...
end

# food はハッシュではなく、Foodクラスのインスタンス（オブジェクト）
@@foods.each do |food|
  # attr_readerが作ったメソッドを使って値を取り出す
  puts food.name #=> メロンパン, スパゲティ ...
end
```

`Food.new` で作られたものは「`Food`オブジェクト」です。このオブジェクトから値を取り出すには、`attr_reader` が自動的に作ってくれた `name` や `calory` といった「ゲッターメソッド」を使います。そのため、`food[:name]` ではなく `food.name` という書き方になります。

## まとめ：今回のドリルの設計思想

ドリル42の `Food` クラスは、「カロリー計算に関するデータ管理の責任をすべて負う」という設計になっています。

- データはクラス変数 `@@foods` で**クラス自身が管理**します。
- データの追加は `Food.input` メソッドが、**入力受付からインスタンス生成、保存までを一手に引き受けます**。
- データの表示は `Food.show_all_calory` メソッドが、**クラスが持つデータを使って整形・出力**します。

この結果、プログラムのメインループは、クラスの内部実装を意識することなく、非常にシンプルに記述できます。

```ruby
# このループは Food クラスの中身を知らなくても良い
while true do
  # ...
  if input == 0
    Food.input           # 「食べ物を入力して」とお願いするだけ
  elsif input == 1
    Food.show_all_calory # 「合計を見せて」とお願いするだけ
    exit
  end
end
```

このように、クラスが持つべきデータをクラス自身で管理し、外部にはシンプルな命令（メソッド）だけを公開する設計は、オブジェクト指向プログラミングにおける非常に重要な考え方の一つです。

## Q&A

**Q: `@@foods = []` の `[]` の中にはどういう形式でデータが入るの？**

A: `Food` オブジェクトがそのまま配列に入る。

```ruby
@@foods = [
  #<Food @name="ラーメン", @calory=500>,
  #<Food @name="カレー", @calory=700>,
  #<Food @name="サラダ", @calory=100>
]
```

`Food.new(name, calory)` で作ったオブジェクトを `<<` で追加しているので、ハッシュじゃなく **Food オブジェクトの配列**になる。だから取り出す時も `food[:name]` ではなく `food.name` になる。
