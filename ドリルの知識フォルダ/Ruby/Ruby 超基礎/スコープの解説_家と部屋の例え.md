# 【超入門】スコープとは？PHP/Rubyの変数が見える範囲を徹底解説

「`while`の中にも`$input`があるのに、なぜエラーにならないの？」
「関数の中と外で同じ名前の変数を使っても大丈夫なのはなぜ？」

これは、プログラミングにおける**スコープ**という非常に重要な概念に関する疑問です。
一言で言うと、**「変数が使える範囲（有効範囲）」**のことです。

このスコープの仕組みを、「家と部屋」の例えで徹底的に解説します。

---

### スコープは「家と部屋」で考えると一瞬でわかる

プログラム全体を一つの大きな**「家」**だと想像してください。

#### 1. グローバルスコープ（家のリビング）

家の「リビング」にあたるのが**グローバルスコープ**です。

- **特徴**: 家のどこからでも見える共有スペース。
- **変数**: リビングに置かれた「テレビ」や「テーブル」（グローバル変数）。

このリビングに置かれた変数は、プログラムのどこからでもアクセスできます。便利ですが、誰でも触れるため、意図せず書き換えられてしまう危険性もあります。

#### 2. ローカルスコープ（個人の部屋）

家の中にある、鍵付きの「個人の部屋」にあたるのが**ローカルスコープ**です。
PHPやRubyでは、**関数（メソッド）を定義すると、この「個人の部屋」が作られます。**

- **特徴**: 部屋の中だけで完結するプライベートな空間。
- **変数**: 部屋の中に置かれた「机」や「ベッド」（ローカル変数）。

部屋の中にある変数は、その部屋の中からしか見たり触ったりできません。外（リビング）からは、部屋の中に何があるかさえ分かりません。

### なぜ同じ名前の変数が使えるのか？

これがスコープの最大のメリットです。

> **リビングに「テレビ」があっても、自分の部屋に「テレビ」を置くことができます。**

これらは同じ「テレビ」という名前ですが、全くの別物です。自分の部屋のテレビのチャンネルを変えても、リビングのテレビには何の影響もありません。

プログラムも同じです。

**【PHPの例】**

```php
$input = "リビングの入力"; // グローバルスコープ（リビング）の変数

// 'register_book' という名前の「個人の部屋」を作る
function register_book() {
    // この$inputは部屋の中だけの変数。外の$inputとは別物！
    $input = "個人の部屋の入力";
    echo "関数の中: " . $input . "\n"; //-> 個人の部屋の入力
}

register_book();
echo "関数の外: " . $input . "\n"; //-> リビングの入力
```

**【Rubyの例】**

```ruby
input = "リビングの入力" # グローバルスコープ（リビング）の変数

# 'register_book' という名前の「個人の部屋」を作る
def register_book
  # このinputは部屋の中だけの変数。外のinputとは別物！
  input = "個人の部屋の入力"
  puts "メソッドの中: #{input}" #=> 個人の部屋の入力
end

register_book
puts "メソッドの外: #{input}" #=> リビングの入力
```

このように、関数という「部屋」を作ることで、変数の有効範囲が区切られます。これにより、他の場所でどんな名前の変数が使われていようと気にすることなく、安全にプログラミングができるのです。

### `while`ループのスコープは？

`while`や`for`などのループは、「部屋」のような強力な壁は作りません。どちらかというと「リビングに置かれた、背の低い衝立（ついたて）」のようなものです。

`while`ループの中で定義された変数は、基本的にはループの外（リビング）からも見ることができます。**スコープを明確に区切るのは、あくまで「関数」**だと覚えておきましょう。

### まとめ

| 概念 | 例え | 特徴 |
| :--- | :--- | :--- |
| **グローバルスコープ** | 家のリビング | プログラム全体で共有。どこからでも見える。 |
| **ローカルスコープ** | 個人の部屋（関数） | 関数の中だけで有効。外からは見えず、安全。 |

スコープを理解することは、変数の名前が衝突するのを防ぎ、コードを安全で整理された状態に保つための第一歩です。
