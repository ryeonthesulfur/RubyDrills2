# なぜインスタンス変数はメソッド経由で渡すのか？【カプセル化の解説】

「クラスの外では、なぜインスタンス変数を（メソッド経由で）渡すの？」
これはオブジェクト指向のとても重要な考え方に関する素晴らしい質問です。

一言で答えるなら、**「クラスの大事なデータを、外から勝手に書き換えられないように守り、クラスを安全で使いやすい『部品』にするため」**です。

これを「金庫と受付窓口」の例えで詳しく解説しますね。

---

### 1. インスタンス変数 (`@name`) は「金庫」の中のデータ

Rubyのクラス内で `@` から始まるインスタンス変数（例: `@name`）は、そのクラスから作られたインスタンス（オブジェクト）だけが持つ、個人的なデータです。

これは、**クラスという建物の中にある「金庫」**のようなものだと考えてください。金庫の中身は非常に大切で、誰でも自由に触れるべきではありません。

Rubyの設計上、この金庫はとても頑丈で、クラスの外から `student.@name` のように直接こじ開けることはできないようになっています。

```ruby
class Student
  def initialize(name)
    @name = name # 金庫の中に名前をしまう
  end
end

student = Student.new("ゆき")
# student.@name #=> エラー！外から金庫は開けられない
```

### 2. なぜ外で値が必要になるのか？

ではなぜ、金庫の中にあるデータを知りたいのでしょうか？
それは、作ったインスタンスの情報を、クラスの外で**「表示」**したり、**「利用」**したりしたいからです。

```ruby
# こういうことをしたい！
puts "生徒の名前は #{student.name} です。"
```

### 3. 「受付窓口」を通して安全に渡す

そこで登場するのが**メソッド**です。メソッドは、金庫の中身を安全に外部に渡すための**「受付窓口」**の役割を果たします。

この窓口を作る一番簡単な方法が `attr_reader` です。

```ruby
class Student
  attr_reader :name # 「name」という名前の受付窓口（ゲッター）を自動で作成

  def initialize(name)
    @name = name
  end
end

student = Student.new("ゆき")
puts student.name #=> "ゆき"（受付窓口を通して、安全に名前を取得）
```

`student.name` と呼び出すと、`Student`クラスが「受付窓口（`name`メソッド）」を通じて、金庫の中にある`@name`の値をコピーして渡してくれます。

### 4. なぜ直接渡さず、わざわざ窓口を通すのか？（最重要）

これが質問の核心ですね。理由は大きく2つあります。

#### 理由1：データを守るため（安全性）

受付窓口（メソッド）を設けることで、**「値の取得は許可するが、書き換えは許可しない」**というルールを作れます。`attr_reader` はまさに読み取り専用の窓口です。

もし金庫を直接触れるようにしてしまうと、意図しない場所で勝手に値を書き換えられてしまう危険性があります。

```ruby
# もし直接書き換えられたら...
student.name = "悪意のあるハッカー" # attr_readerだけならエラーになるので安全！
# データが壊れ、プログラム全体が予期せぬ動きをする原因になる
```

#### 理由2：将来の変更に強くするため（メンテナンス性）

これがプログラミングにおいて非常に重要な**「カプセル化」**という考え方です。

例えば、将来的に「名前を姓と名に分けて管理したい」という仕様変更があったとします。

```ruby
# 【変更後】
class Student
  # attr_reader :name # ← この窓口はそのまま！
  
  def initialize(last_name, first_name)
    @last_name = last_name
    @first_name = first_name
  end

  # 受付窓口の中の仕組みだけを変える
  def name
    return "#{@last_name} #{@first_name}"
  end
end

# クラスの内部実装は変わったが...
student = Student.new("山田", "花子")

# クラスの外側の呼び出し方は一切変えなくて良い！
puts student.name #=> "山田 花子" 
```

このように、**クラスの内部構造（金庫の仕組み）が変わっても、外部とのやり取りをする窓口（メソッド）さえ同じであれば、クラスの外側のコードに影響が出ません。**

これにより、クラスを独立した「部品」として安心して使うことができ、修正も容易になります。

---

### まとめ

| 質問 | 答え |
| :--- | :--- |
| **インスタンス変数とは？** | クラスの「金庫」に保管された大事なデータ (`@name`) |
| **なぜ外で値が必要？** | 表示や他の処理で「利用」したいから |
| **どうやって渡す？** | `attr_reader` などの「受付窓口（メソッド）」を通して安全に渡す |
| **なぜ直接渡さない？** | ①**安全性**: 勝手な書き換えを防ぐため<br>②**メンテナンス性**: 将来の内部変更に強くするため（カプセル化） |

この「カプセル化」は、オブジェクト指向プログラミングの根幹をなす非常に重要な概念なので、ぜひ覚えておいてください！
