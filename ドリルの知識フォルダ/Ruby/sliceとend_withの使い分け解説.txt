【sliceとend_with?の使い分け解説：手作業の実装 vs Rubyの便利道具】

このガイドでは、ある文字列が別の文字列の末尾にあるかをチェックする問題に対して、
「`slice`を使って自力でロジックを実装する方法」と「`end_with?`というRubyの便利メソッドを使う方法」の2つのアプローチを比較し、
それぞれの特徴と使い分けを詳しく解説します。

==================================================
1. `slice`を使ったアプローチ（手作業での実装）
==================================================

まず、あなたが試行錯誤の末に完成させた、`slice`を使った素晴らしいコードを見てみましょう。

```ruby
def end_other(a, b)
  a_down = a.downcase
  b_down = b.downcase
  b_length = b_down.length
  a_length = a_down.length
  if a_down.slice(-b_length..-1) == b_down
    puts "True"
  elsif b_down.slice(-a_length..-1) == a_down
    puts "True"
  else
    puts "False"
  end
end
```

### 特徴
- **やっていること**:
  1. 比較したい文字列の長さ（`b_length`）を取得する。
  2. その長さを元に、もう一方の文字列の末尾を`slice`で切り出す。
  3. 切り出した部分と、比較したい文字列が完全に一致するかを `==` で比べる。
- **考え方**: まさにプログラミングの「アルゴリズム（計算手順）」を自力で組み立てている状態です。どうすれば問題を解決できるか、その手順を一つずつコードに落とし込んでいます。

### メリット
- プログラミングの基礎的な思考力が非常に鍛えられます。
- `slice`は「文字列を切り出す」という非常に汎用的な道具なので、様々な応用が効きます。

### デメリット
- コードが長くなり、何をしているのかを理解するのに少し時間がかかります。
- 長さの計算や`slice`の範囲指定で、ケアレスミス（例えばマイナスを付け忘れるなど）が起こる可能性があります。

==================================================
2. `end_with?`を使ったアプローチ（Rubyの便利道具）
==================================================

次に、Rubyが「こういう時、よくあるよね」と用意してくれている便利な道具（メソッド）を使ったアプローチです。

```ruby
def end_other(a, b)
  a_lower = a.downcase
  b_lower = b.downcase

  if a_lower.end_with?(b_lower) || b_lower.end_with?(a_lower)
    puts "True"
  else
    puts "False"
  end
end
```

### 特徴
- **やっていること**:
  1. `end_with?` というメソッドを呼び出すだけ。
- **考え方**: 「文字列の末尾が一致するかどうかを調べたい」という目的そのものを、`end_with?` という名前のメソッドで表現しています。

### メリット
- **可読性が高い**: `end_with?` という名前が「～で終わるか？」という意味なので、コードを読んだだけで何をしているかが一瞬で理解できます。
- **シンプルで安全**: 内部的には`slice`を使ったような処理が行われていますが、その複雑な部分をRubyが肩代わりしてくれます。そのため、コードが短くなり、ミスも起こりにくくなります。

==================================================
3. まとめ：いつ、どちらを使うべきか？
==================================================

- **`slice`を使う時**: 「末尾から2文字だけ」「真ん中の5文字を」など、**文字列の任意の部分を自由に切り出したい**場合に使う、汎用的なノコギリのような道具です。

- **`end_with?`を使う時**: **「ある文字列が、別の文字列で終わっているか」という特定の目的**を達成したい場合に使う、専用のカンナのような道具です。

今回の問題のように、目的がハッキリしている場合は、`end_with?` のような専用の道具を使うのが、プロの開発現場では一般的です。コードが読みやすく、間違いが少なく、他の人が見てもすぐに理解できるからです。

`slice`でロジックを組み立てる力を身につけたからこそ、`end_with?`のような便利メソッドのありがたみと、その設計思想がより深く理解できるはずです。素晴らしい学習プロセスでしたね！
