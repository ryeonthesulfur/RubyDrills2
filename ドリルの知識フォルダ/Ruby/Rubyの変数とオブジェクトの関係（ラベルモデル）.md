## 1. Rubyの変数は「名札」である

Rubyでは、変数はオブジェクト（データの実体）そのものではなく、オブジェクトに付けられた**「名札（ラベル）」**だと考えるとわかりやすい。

```ruby
str = "hello"
```

このとき起きていること：
- メモリのどこかに `"hello"` というオブジェクトが作られる
- `str` は、そのオブジェクトを指す「名札」として機能する
- `str` という箱の中に `"hello"` が入っているわけではない

```
str ──→ [ "hello" オブジェクト ]
```

## 2. メソッドに渡すと何が起きるか

変数をメソッドに渡すと、**「名札がコピー」される**。

オブジェクト本体はコピーされない。メソッドの内側と外側が、別々の名札を通じて**同じオブジェクト**を指している状態になる。

```ruby
def add_item(list)
  list << "バナナ"   # list という名札経由でオブジェクトを変更
end

cart = ["りんご"]
add_item(cart)

puts cart.inspect  #=> ["りんご", "バナナ"]  ← 元の配列が変わっている
```

**何が起きているか：**

```
呼び出し前：  cart ──→ [ "りんご" ]
渡した後：    cart ──→ [ "りんご" ]
              list ──↗（同じオブジェクトを指している）

list << "バナナ" を実行すると：
              cart ──→ [ "りんご", "バナナ" ]
              list ──↗（同じオブジェクトなので cart から見ても変わっている）
```

つまり、**メソッドの中でオブジェクトの中身を変えると、外側の変数から見ても変わる**。

## 3. Rubyのルールは何に対しても一貫している

Rubyでは「すべてがオブジェクト」なので、**配列でも文字列でも数値でも、渡し方のルールは常に同じ**。

- 配列を渡す → 名札のコピー
- 文字列を渡す → 名札のコピー
- 自作クラスのインスタンスを渡す → 名札のコピー

何を渡しても同じルールが適用されるため、「これはコピーされる？されない？」と迷う必要がない。

```ruby
def change(obj)
  obj << " world"
end

str = "hello"
change(str)
puts str  #=> "hello world"  ← 文字列も同様に変わる
```

---

## 4. まとめ

| 概念 | 内容 |
|:-----|:-----|
| **変数の正体** | オブジェクトを指す「名札」 |
| **メソッドに渡すと** | 名札がコピーされる（オブジェクト本体はコピーされない） |
| **メソッド内で中身を変えると** | 外側の変数から見ても変わる（同じオブジェクトを指しているため） |
| **一貫性** | 配列・文字列・インスタンスすべて同じルール |

> Rubyは「何を渡してもラベルがコピーされるだけ」という1つのルールで統一されている。
